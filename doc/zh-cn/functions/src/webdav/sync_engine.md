# lib/src/webdav/sync_engine.dart

由 `StorageAdapter`、`ModuleRegistry` 和按操作的 `WebDAVConfig` 参数化的泛型 WebDAV 编排。它组合 P2.4 原子 I/O、P2.5 传输/远程锁原语和应用自有的模块回调，而不导入应用模型。

## 公共声明

| 声明 | 种类 | Tier | 用途 |
|---|---|---|---|
| `WebDavClientFactory` | 类型别名 | A | 构建一个绑定到当前提供配置的传输。 |
| `SyncClock` | 类型别名 | A | 注入 UTC 时间，用于确定性的锁测试。 |
| `SyncIdGenerator` | 类型别名 | A | 注入客户端 ID/上传令牌生成。 |
| `EngineSyncResult` | 类 | A | 返回成功、拼接错误、待定状态和警告。 |
| `EnginePendingModule` | 类 | A | 保留一个模块描述符和不透明的待定合并结果。 |
| `EnginePendingSync` | 类 | A | 保留有序的待定模块和扁平化冲突。 |
| `WebDavSyncEngine` | 类 | A | 运行配置、同步、最终化、图像和强制工作流。 |

索引计 47 个声明，包括构造函数、getter、公共操作和私有状态机辅助。

## 构造

`WebDavSyncEngine` 需要一个应用存储适配器、有序模块注册表，以及按应用的兜底远程路径。`failFastOnDownloadError` 默认为 false；MyAnime 可以在集成时设为 true。客户端工厂、时钟和 ID 生成器是可注入的测试接缝。每个应用需要一个长生命周期引擎，以保留操作守卫、进度通知器和粘性本地变更信号。

公共 sync/force/finalize 方法按调用接受 `WebDAVConfig`。这保留了当前使用未保存配置页值的手动操作，而不是静默重新加载持久化配置。

## 常规同步

常规流程是：

1. 用 `Sync already in progress` 拒绝重叠的同步/强制工作。
2. 尽力而为地在远程应用根目录 MKCOL。
3. 加载/创建 `.sync_base/client_id.txt` 并检查 `upload_lock.json`。
4. 在任何模块 GET 之前获取远程 `.lock`，使用强 ETag `If-Match` 或 `If-None-Match: *`；锁 PUT 保持免重试。
5. 按注册表顺序处理模块。
6. 即使模块有冲突/逐文件错误，也运行仅引用添加式图像同步。
7. 释放匹配的远程/本地锁状态并发布终止进度。

逐模块分支行为：

| 本地 | 远程 | 动作 |
|---|---|---|
| 缺失 | 404 | 跳过；保留任何过期的基线。 |
| 缺失 | 找到 | 把远程原始 JSON 复制到本地和基线；不做模块解析。 |
| 存在 | 404 | 强制上传本地原始 JSON，然后保存基线。 |
| 存在 | 逐字节相同 | 保存原始基线；不合并/上传。 |
| 存在 | 不同 | 读取基线，调用模块合并，若最初无冲突则重新读取一次本地，然后进入待定或变换/写入/上传/基线。 |
| 任意 | 非 404 错误 | 逐文件错误并继续，除非配置了快速失败。 |

合并后的本地 JSON 在 PUT 之前写入，但其基线只在 PUT 成功之后变化。因此失败的上传会留下新本地数据和粘性本地变更信号、配上旧基线，使下一次同步重新合并。

## 待定与最终化

仅冲突的同步可以是 `success: true` 且待定状态非空，与既有应用一致。最终化重新获取 `.lock`，使用每个模块的解决构建器和合并后变换，全新下载远程模块，应用可选保留上下文，写入本地、上传，并在成功时保存基线。

兼容性限制是刻意的：最终化不共享同步/强制守卫、不发出进度，也不重新合并对话框打开期间被改变的已知字段。它的全新 GET 防止上传覆盖一个不可读的远程，并为 MyDay 提供保留上下文。这些是既有的应用语义；在零变更抽取之外改变它们是另一回事。

## 图像

图像引用按注册表顺序累积，每个模块先本地后远程。常规同步在 `images/` 上 MKCOL 和 PROPFIND；列目录失败用固定警告跳过该阶段。否则它上传本地有而远程缺失的引用图像，然后按引用顺序下载远程有而本地缺失的引用图像。同名文件和孤儿文件绝不覆盖或删除。

强制上传在列目录失败时退回上传每个被引用的本地图像。强制下载不加锁、只下载被引用的远程图像，并在列目录失败时报告固定警告。

## 强制操作

`forceUpload` 持有 `.lock`，不加校验/合并地上传每个既存本地模块的原始内容，在每次成功 PUT 后保存基线，跳过缺失的本地模块，并在第一次数据失败时中止。

`forceDownload` 不加锁、按注册表顺序下载，远程 404 时保留本地/基线，只做 `jsonDecode` 语法检查，原子地增量写入原始远程 JSON 和基线，并在后面的模块失败时保留前面已写入的内容。

## 本地状态

`loadConfig` 只在键缺失/null 时应用 `defaultRemotePath`；显式的空路径仍指 WebDAV 账户根。配置 JSON 保持紧凑。基线读取把错误吞为无基线；写入使用 P2.4 原子替换。`consumeLocalDataChanged` 是读后重置，表示"自上次消费以来发生过变化"，而不仅是最近一次操作。
